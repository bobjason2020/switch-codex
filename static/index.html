NewAPI 自动探测

探测任务保存在 SQLite 数据库（data/switchyard.db）。每个任务按自己的间隔从供应商的 /api/user/groups（失败时回退 /api/pricing）拉取分组倍率， 自动同步到指定上游的 multiplier 与 priority；可新增、编辑、删除多条。

名称 状态 供应商 分组 目标上游 间隔 排序 上次探测 操作

倍率来源：user/groups 或 pricing.group_ratio；同步后上游会标记 ratio_source=newapi 并记录对应探测 ID。「排序」列微调上游优先级： 优先 -0.1 / 同级 0 / 靠后 +0.1，级联探测按优先级先后执行。

新增 NewAPI 探测

新增上游

openai / Deepseek / Grok 自动使用对应路由池，无需填写模型信息；自定义需选择或新建 Model 池。

上游的 model 只决定路由池。DeepSeek 上游统一使用池 deepseek；实际请求模型默认带 deepseek-v4-flash / deepseek-v4-pro，可手动增删。

每行填「模型名 / 实际模型名」，实际模型名留空则与该模型名相同； 未列入的模型不会使用该上游。列表为空会自动补回该池默认模型： openai 带 gpt-5.6-luna / terra / sol，deepseek 带 deepseek-v4-flash / pro， grok 带 grok-4.6，其他池带池模型名。

仅当上游没有可用的 /v1/responses 端点时开启：请求会转换为 chat/completions 发出并转回 responses 格式返回。

开启后 Claude Code 请求（/v1/messages）会以 Anthropic 格式直接透传该上游 {base_url}/messages（x-api-key 认证），零转换、thinking/工具无损； 未开启的上游仍走 Responses 转换层。适用于原生提供 Anthropic 接口的上游。
